## 機能概要

SurrealDB の Record Access を使ってユーザーを管理し、`POST /auth/signup` でユーザー登録、`POST /auth/signin` で認証を行う。認証成功時は JWT（有効期限 24 時間）を発行して返す。保護されたルートは `auth_middleware` で JWT を検証する。

## 意図

CMS の操作を認証済みユーザーのみに限定し、SurrealDB のアクセス制御と JWT の組み合わせでステートレスな認証を実現する。

## 主要なメンバー

- `POST /auth/signup` — メール・パスワードでユーザー登録し JWT を返す
- `POST /auth/signin` — メール・パスワードで認証し JWT を返す
- `JwtClaims { sub, exp }` — JWT のペイロード（sub: ユーザーID、exp: 有効期限）
- `auth_middleware` — Authorization ヘッダーの Bearer トークンを検証する Axum ミドルウェア
- `AppError::Unauthorized` → 401 Unauthorized
- `AppError::Conflict { message }` → 409 Conflict（重複ユーザー登録時）

## シナリオ

### 新規ユーザーが登録する

1. クライアントが `POST /auth/signup` にメールとパスワードを送信する
2. SurrealDB の Record Access でユーザーを作成する
3. サーバーが JWT（有効期限 24h）を発行してレスポンスする

### 既存ユーザーがサインインする

1. クライアントが `POST /auth/signin` にメールとパスワードを送信する
2. SurrealDB の Record Access で認証する
3. サーバーが JWT を発行してレスポンスする

### 既に登録済みのメールで登録しようとする

1. クライアントが既存のメールで `POST /auth/signup` を送信する
2. SurrealDB が重複エラーを返す
3. サーバーが 409 Conflict を返す

### 無効なトークンで保護されたルートにアクセスする

1. クライアントが無効または期限切れの JWT を送信する
2. `auth_middleware` が JWT 検証に失敗する
3. サーバーが 401 Unauthorized を返す
