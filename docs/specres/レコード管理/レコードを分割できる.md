## 機能概要

1つのレコードを複数に分割する API (`POST /records/{collectionId}/{recordId}/split`) を提供する。指定された数値フィールドから値を減算して新規レコードを作成する。元レコードの数値フィールドは減算後の値に更新される。

## 意図

LLM エージェントがデータの分配や分割を行えるようにする。例えば、在庫を複数の倉庫に分配する場合や、残高を複数のアカウントに振り分ける場合に使用する。

## 主要なメンバー

- `SplitRecordRequest` — 分割するフィールドと値の配列
- `SplitRecordResponse` — 元レコードと新規レコードの配列
- `CollectionRepository::split_record()` — レコード分割の実行

## シナリオ

### 正常系: レコードを分割して数値フィールドを減算する

1. クライアントが `POST /records/{collectionId}/{recordId}/split` に以下を送信する:
   ```json
   {
     "splits": [
       { "quantity": 30 },
       { "quantity": 20 }
     ]
   }
   ```
2. API が元レコード（例: `quantity: 100`）を取得する
3. 分割ごとに新規レコードを作成する:
   - 新規レコード1: `quantity: 30`（他フィールドは元レコードをコピー）
   - 新規レコード2: `quantity: 20`（他フィールドは元レコードをコピー）
4. 元レコードの `quantity` を `100 - 30 - 20 = 50` に更新する
5. 200 OK で元レコードと新規レコード配列を返す:
   ```json
   {
     "original": { "id": "...", "data": { "quantity": 50, ... } },
     "splits": [
       { "id": "...", "data": { "quantity": 30, ... } },
       { "id": "...", "data": { "quantity": 20, ... } }
     ]
   }
   ```

### 異常系: 減算結果が負になる

1. クライアントが元の値より大きい合計値で分割を要求する
2. 400 Bad Request で `VALIDATION_ERROR` を返す（メッセージ: "Insufficient value for field 'quantity'"）

### 異常系: 指定フィールドが数値でない

1. クライアントが文字列フィールドを分割対象に指定する
2. 400 Bad Request で `VALIDATION_ERROR` を返す

### 異常系: 元レコードが存在しない

1. クライアントが存在しないレコード ID で分割を要求する
2. 404 Not Found で `NOT_FOUND` を返す
