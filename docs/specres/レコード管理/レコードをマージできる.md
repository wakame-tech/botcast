## 機能概要

複数のレコードを1つにマージする API (`POST /records/{collectionId}/merge`) を提供する。指定された数値フィールドは加算され、その他のフィールドはマージ先レコードの値が優先される。マージ元レコードはオプションで削除できる。

## 意図

LLM エージェントが重複データの統合や、分散したデータの集約を行えるようにする。例えば、同一人物の複数レコードを統合する際に、ポイントや金額などの数値フィールドを合算できる。

## 主要なメンバー

- `MergeRecordsRequest` — マージ元レコード ID 配列、加算対象フィールド、削除オプション
- `CollectionRepository::merge_records()` — レコードマージの実行

## シナリオ

### 正常系: レコードをマージして加算フィールドを合算する

1. クライアントが `POST /records/{collectionId}/merge` に以下を送信する:
   ```json
   {
     "source_record_ids": ["rec1", "rec2"],
     "target_record_id": "rec1",
     "add_fields": ["points", "balance"],
     "delete_sources": true
   }
   ```
2. API が全ての対象レコードを取得する
3. `add_fields` で指定されたフィールドの値を合算する
4. その他のフィールドは `target_record_id` の値を維持する
5. マージ先レコードを更新する
6. `delete_sources: true` の場合、マージ元レコード（target 以外）を削除する
7. 200 OK でマージ後のレコードを返す

### 正常系: マージ元を削除せずにマージする

1. クライアントが `delete_sources: false` でマージを要求する
2. マージ処理を実行する
3. マージ元レコードは削除されず残る
4. 200 OK でマージ後のレコードを返す

### 異常系: 指定したレコードが存在しない

1. クライアントが存在しないレコード ID を含むマージを要求する
2. 404 Not Found で `NOT_FOUND` を返す

### 異常系: 加算対象フィールドが数値でない

1. クライアントが文字列フィールドを `add_fields` に指定する
2. 400 Bad Request で `VALIDATION_ERROR` を返す
